# US-001-06

As a security-conscious user, I want to have failed login attempts validated server-side against bcrypt hashes rather than client-side, so that ensure credential checks cannot be bypassed in the browser, protecting the integrity of the authentication success KPI. - Given the client submits an email and password to POST /api/login, when the server receives the request, then it compares the password against the stored bcrypt hash server-side before responding - Given a client sends a malformed or missing credential payload to POST /api/login, when the server processes the request, then it returns an error response without attempting a bcrypt comparison or issuing a cookie - Test case: the server receives the request - Test case: [error] the server processes the request
